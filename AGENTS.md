# AGENTS.md

## Context

input-automation is a Python program to automate inputs on Linux (Wayland).
It exposes both a PySide6 desktop GUI and a CLI sharing one core engine.
Primary target is GNOME on Wayland (Fedora); wlroots-based compositors are
best-effort via fallback backends.

Users can see all connected input devices (keyboard, mouse, gamepads) and
bind macros to their inputs. The program emits output events (mouse move,
clicks, scroll, key presses) through virtual uinput/evdev devices, so games
and applications receive them as if they came from real hardware.

Visual automation: the program captures the screen continuously via the
GNOME portal PipeWire screencast backend and analyzes frames with OpenCV —
template matching, pixel color thresholds, and region-based health/energy
bar measurement. Device events and screen changes act as triggers that can
be linked to complex macros.

Macro model: declarative YAML files are the source of truth
(`~/.config/input-automate/macros/`), validated against a schema on load,
edited/generated by the GUI, with an escape hatch for custom Python macro
code for complex logic. The escape hatch is plain `.py` files loaded
dynamically from the macros directory (hot-reloadable; loading untrusted
files is at the user's own risk and must be documented as such).

Scope decisions: capture targets the primary monitor in v1 (multi-monitor
support later). A persistent JSONL execution log under `logs/` records when
macros fire and what they did. An interactive visual region picker is a
must-have for v1 (ships with the GUI milestone).

Architecture decisions (confirmed):
- Input capture: raw evdev reading of /dev/input (requires input group / root
  udev rule, works system-wide, catches all physical devices).
- Output injection: uinput virtual devices (requires udev rule for uinput).
- Macro engine: full conditional logic — if/else based on screen state,
  loops, and variables. Not just linear sequences.
- Vision: pixel color / region threshold analysis only for v1 (no OCR or
  object detection planned).
- Recording & replay: a core feature. Capture user actions via evdev, save
  as macros, and replay them (same macro engine, loop + conditional support).

## Stack

- Python >= 3.12
- PySide6 — GUI (Qt official LGPL binding)
- python-evdev — device reading and event capture
- python-uinput — virtual output devices (mouse/keyboard injection)
- OpenCV (opencv-python) — image analysis, template matching
- PyYAML — macro definitions
- Typer — CLI framework
- Pydantic — macro schema validation
- pytest, ruff, mypy — quality gates

## Deployment

- Official install method: pipx from GitHub release tags
  (`pipx install git+https://github.com/SebastianDeOliveiraSpitz/input-automate@<tag>`,
  SSH remote for pushes: git@github.com:SebastianDeOliveiraSpitz/input-automate.git).
  PySide6 bundles its own Qt, so no system Qt is needed on the target.
- Every release tag ships the same installer script `install/system-setup.sh`
  (udev rule for uinput, `input` group check, optional systemd user unit for
  the always-on macro daemon). pipx cannot do system-level setup, so the
  script must be run once per target machine and is idempotent.
- GUI usage targets real Fedora GNOME machines; the daemon + CLI can also run
  on headless hosts.
- Development happens on the headless mgmt-vm: GUI tests (pytest-qt) must run
  with `QT_QPA_PLATFORM=offscreen`; real-GUI behavior is verified on fedora1.
- PyInstaller binary and RPM packaging are out of scope for v1 (revisit only
  if a no-Python target machine appears).
- AppImage rejected: bundling PySide6 + OpenCV (~250 MB, fragile tooling) buys
  nothing here because the udev rule/system script is required anyway.

## Rules

- Use KISS and DRY
- Commit and push also small changes
- Verify before every commit: `ruff check .`, `mypy` (configured targets), `pytest`
- Work one TASKS.md task at a time, in listed order; remove its line when done
- Design for headless testability: core engine must run without GUI or real devices (mock/fake backends)
- Never log raw input device data or keystroke contents; macro/event data may be logged in sanitized form
- Runtime writes only under `~/.config/input-automate/` and `logs/`; gitignore both with `!.gitkeep`
- Linux-only (Wayland); no Windows/macOS support planned
